# Service virtualization

Two things stand in for the outside world so the suite can drive cases that are hard
to provoke on purpose: a fake PayFast, and a real device simulator.

## Why not mocks in the test project

A mock written alongside the code it tests only ever agrees with itself. Both ends
come from one reading of the spec, so a misreading passes. These two are different:

- **The device simulator is not a stub.** It is the same `courtlogic::CourtBox`, the
  same `lib/protocol` codec and the same relay auto-off timer the ATmega runs, behind
  a POSIX HAL and a TCP socket. If the firmware's decoder rejects a frame, so does
  this. That makes it evidence rather than a second opinion.

- **The PayFast imposter is honest about what it proves.** It does not prove the
  integration works against PayFast. The signature algorithm is pinned separately by
  `src/contracts/payfast`, generated by an independent implementation; the imposter
  proves the *other* half — that the API's handling of a callback is right, that a
  replay is refused, that a bad signature is refused, and that a decline is not
  quietly treated as a success. **The first live transaction is still a real
  milestone.**

## Both a process and a sidecar, deliberately

Nothing here depends on Docker. The daemon is unavailable in some CI setups and in
the environment this was built in, and a test suite that can only run under Docker is
a test suite that quietly stops running.

```bash
# As plain processes
make virt-up        # mountebank via npx, simulator as a native binary
make virt-down
```

`docker-compose.test.yml` provides the same two services as sidecars, for the club's
own machine and for CI runners that prefer containers. They are the same
configuration read from the same files — the compose file mounts
`test/virtualization/payfast/imposter.json` rather than restating it.

## Ports

| Service | Port | What it is |
|---|---|---|
| mountebank admin | 2525 | imposter management |
| PayFast imposter | 4545 | what the API is pointed at instead of PayFast |
| device simulator | 5555 | the Mega's serial protocol over TCP |

## Provoking each case

| Case | How |
|---|---|
| Successful checkout | any `m_payment_id` |
| Declined payment | `m_payment_id=decline…` |
| Gateway timeout | any path containing `timeout` |
| Replayed ITN | POST the same callback body twice — the API's filtered unique index on `ExternalReference` is what refuses it, not the imposter |
| Bad signature | alter any field after signing — refused by `PayFastSignature.Verify` |
| Rollover in the device | `--start-ms 4294963200` puts the 49.7-day `millis()` wrap four seconds after launch |
