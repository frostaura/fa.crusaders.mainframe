# Complexity baseline — a RATCHET, not an amnesty.
#
# Every function listed here already exceeded the gate (CCN 15 / length 200 /
# 6 params) when the gate was introduced. Listing them freezes the debt: they
# cannot get worse without being noticed, and NEW code is held to the real
# threshold from day one.
#
# The right way to remove a line from this file is to simplify the function.
# Adding a line requires a reviewer to agree the complexity is essential.
#
# A note on the Minimal API entries: lizard scores `MapXxxEndpoints` as one
# function, but it is really N independent route handlers, each individually
# simple. Those are measurement artifacts rather than genuine complexity, and
# they resolve naturally as endpoints are split out during the device work.
#
# THE NAMES HERE ARE LIZARD'S, NOT C#'s, and the two can disagree. lizard's C#
# parser scopes a function under the most recently DECLARED type, not the type
# that encloses it — so a method sitting directly BELOW a nested class is
# reported inside that class. `TopUpEndpoints.MapTopUpEndpoints` has been
# reported both ways: as `FailureCodes::MapTopUpEndpoints` when the nested
# `FailureCodes` class sat above it, and as `TopUpEndpoints::MapTopUpEndpoints`
# — which is what it reports TODAY — when it sits below. An entry written from
# the source rather than from lizard's own output matches nothing and the gate
# stays red while looking whitelisted. Copy the name out of `make complexity`'s
# warning line; never type it from the C#.
#
# AND THE SCOPING IS NOT STABLE, so one name is not enough. Moving the nested
# `FailureCodes` class below the map method — done to make the entry match —
# flipped lizard's report the other way, to `TopUpEndpoints::MapTopUpEndpoints`,
# and the gate went red on a file nobody had edited. A whitelizard entry keys on
# lizard's reported name, so ANY refactor that changes how the parser scopes a
# method silently voids it in one direction or the other. Both names for the one
# function are listed for that reason: whichever way the parser reads the file,
# the ratchet holds and the function is still frozen at its current numbers.
#
# It bit twice in one day, from both sides at once: one round moved `FailureCodes`
# below `MapTopUpEndpoints` while another, in parallel, renamed the entry to
# `FailureCodes::`. Each was green alone and the merge of the two was red. Listing
# both names is what makes the entry survive that.
#
# NEITHER OF THE TWO IS DEAD WEIGHT, however redundant one looks on any given day.
# Only one of them matches at a time — the other is what catches the next move —
# so deleting "the one that isn't firing" restores exactly the failure this pair
# exists to prevent. Re-checked 2026-09-06 with lizard 1.24.0: the file as it
# stands reports `TopUpEndpoints::MapTopUpEndpoints` (CCN 26, length 237), the
# same file with `FailureCodes` moved above the map method reports
# `FailureCodes::MapTopUpEndpoints` at identical numbers, and `make complexity`
# is green either way only because both lines are here. `RepositoryPostureTests`
# asserts both are present, so a tidy-up that drops one goes red in the suite
# rather than months later on somebody else's unrelated commit.
#
# PhotoPicker is a MEASUREMENT ARTIFACT of the same kind as the Minimal API entries above,
# not complexity. lizard reports it at 9 PARAM, and by every other measure it is one of the
# simplest components in the product: CCN 5, 33 NLOC, 46 lines. React passes exactly one
# argument — the props object — and lizard counts each destructured member of it as a separate
# parameter, so the number says "this component has eight props", which is an ordinary API for
# a form control (value, onChange, two status callbacks, label, hint, required, disabled).
# The repo already carries six TSX components here for this reason.
#
# It is listed rather than "fixed" because every way to satisfy the count makes the code worse:
# bundling label and hint into a `copy` object, or taking `props` and destructuring on the next
# line, both move the same eight names one line down and buy nothing. If a reviewer disagrees,
# the change to make is a smaller component, not a smaller signature.
