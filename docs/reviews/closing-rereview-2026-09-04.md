# Crusaders Mainframe — Court-Light System: Closing Adversarial Re-Review

**Date:** 2026-09-04 · **Scope:** branch `claude/e2e-fix-programme` (21 commits ahead of `main`, working tree clean at synthesis) reviewed against the 30 confirmed defects of the 2026-08-24 review plus the programme's own N1–N4 notes and the C6 residual · **Method:** independent closure audit of every original finding, then adversarial finders across six dimensions with independent refuters per surviving finding · **Constraint honored throughout: the physical wiring is fixed and no finding below proposes changing it.** · **Caveat:** the reference pack the brief cites does not exist on disk; every branch of this review worked from the review document, the tree and the git history.

## 1. Verdict

The claim "the end-to-end system is now flawless given the fixed wiring" is false, but the falsity has changed character completely. On 2026-08-24 the headline flow — book online, scan at the box, lights on — did not exist by any path: no clock seed, no roster, no activation endpoint, no four-court device model, walk-up charging the wrong court, attendance never recorded. Every one of those seven criticals is now genuinely closed, with backend tests, firmware host tests and a shared protocol corpus pinning each one, and 25 of the 30 original findings plus N1–N3 are fully closed; the remaining five are partially closed on documentation and memory-store residue, not on code. That is a real system where there was none. What this pass found instead is that the programme built a working online path and, in doing so, shipped **one new critical and seven new highs**, most of them introduced by the fixes themselves: the CI-signed OTA image carries no WiFi credential, so the first over-the-air release takes every box off the network permanently; the documented gateway makes that OTA URL unreachable twice over; the six-hour event clamp re-creates the exact refund-and-penalise-the-member-who-played outcome that C6 was closed to eliminate, for any outage longer than six hours; the `!AUTH` fix opens an unowned lights-off on any court to anyone holding a random barcode while locking out the paying member; a replayed discovery OFFER strips a box's credential and lets it be repointed; an admin's Revoke click makes a box permanently unregistrable; and behind the always-present nginx the whole club shares one ten-per-minute auth bucket that the new auto-refreshing Court Code page consumes. Twelve further mediums and one low survived verification, one finding was refuted, and 20 leads were dropped over the verification cap. The wiring remains sound and nothing here touches it. The honest statement is: the system now works when nothing goes wrong, and several of the things that will go wrong at a club — a firmware release, a long WiFi outage, a league-night crowd, an admin pressing a button the UI offers — still take courts dark or move money the wrong way. It must not go live until the critical and the seven highs are closed.

## 3. New findings, ranked by severity

All verdicts CONFIRMED by independent adversarial verification unless marked. Severities are the verifiers' final calls. Two pairs of finder reports converged on the same defect and are merged (6, 4); the merge is noted. "Programme" = introduced or made reachable by this branch.

### CRITICAL

**1. The CI-signed OTA image carries no WiFi credential — the first over-the-air release takes every box off the network for good.** *Programme-introduced (the empty-SSID default predates the branch at `167b5b4`; Phase 5a/5b `7c2f13f`/`7347a80` made a runner-built image the zero-config Stable release).*
Files: `.github/workflows/ci.yml:373-438`; `src/iot/src/court_bridge/main.cpp:96-110,1368-1373`; `src/backend/.../Services/OtaCatalogue.cs:128`; `src/backend/.../Endpoints/DeviceEndpoints.cs:104-107`; `.gitignore:112`.
The club SSID/password exist only as compile-time macros from the gitignored `secrets.h`; `main.cpp:96-110` defaults `WIFI_SSID ""` and says so ("refuses to join a network"); `setup()` sets `WiFi.persistent(false)` and calls `WiFi.begin` only when the SSID is non-empty; no store key for WiFi exists though `EepromStore.h:22`/`FakeStore.h:45` reserve slots. `iot-sign` builds on `ubuntu-latest` with only `OTA_PRIVATE_KEY` in env, signs exactly that binary, and `build-backend-*` bakes it; `OtaCatalogue.Stable()` offers the baked manifest with zero configuration; the heartbeat offers it to every box whose `RunningVersion` differs; `UpdatePolicy.cpp:56-71` installs anything newer; `BootGuard.h:1-14` states there is no rollback slot.
*Club-facing failure:* a developer bumps `FW_VERSION` and merges. Within one heartbeat interval every box installs a credential-less build and reboots with an empty SSID. No heartbeat, no online activation; the roster ages out after six hours and refuses every scan; walk-ups need the network. *Fix (wiring-preserving):* move SSID/password into the LittleFS/EEPROM store, provisioned once over USB or via the claim flow, so a CI image inherits them; until then make `iot-sign` refuse to package (or the catalogue refuse to offer) an image built without credentials, and say so in `deployment.md` and go-live item 6.

### HIGH

**2. The six-hour `occurredAt` clamp destroys the late-activation reversal for any outage longer than six hours — the member who played is refunded, penalised, and cannot be repaired.** *Programme-introduced (`MaxEventAge` arrived in `04f1198`; absent on `main`). Two finders converged independently on this defect; merged.*
Files: `src/backend/.../Endpoints/DeviceEventEndpoints.cs:153,175-181,252-256,373-378`; `Services/AccessCodeService.cs:68,154-163`; `Domain/AccessCode.cs:61`; `Webhooks/RetentionWorker.cs:25,100-106`; `src/iot/lib/eventq/include/eventq/EventQueue.h:16-19`; `platformio.ini:151`; `DeviceEventHttpTests.cs:1096-1128`.
`TimeOf` replaces a correctly computed scan time with `now` when the event is older than six hours; `ResolveAsync(code, occurredAt)` then judges code liveness at upload time, and a booking-activation code expires at `EndsAt + grace`, so any slot that ended more than six hours before upload resolves to `unresolved` — nothing stamped, `ReverseNoShowAsync` (its single caller is this path) never reached, the batch acknowledged, the box releases its only evidence. The clamp's justification ("the queue is persisted across a power blink") is false: `EventQueue.h` says the ring is RAM-only and uptime arithmetic is exact within a boot, so the only real trigger is precisely the "two-day outage" `README.md:192-199`, `EventQueue.h:17-18` and `go-live-checklist.md:183-184` promise the queue survives. `RetentionWorker` purges codes 24–48 h after expiry, making the loss permanent; the audit row additionally reports `device.event_time_clamped` ("counter is broken") when it is not. The pinned "eight hours behind" test uses a booking that started two minutes ago, a combination that cannot occur in the field, so the suite is green while the real case fails.
*Club-facing failure:* router fails 17:30, box admits the evening from its roster, staff fix it at 08:00. Every event is clamped; every member who played is refunded 70 %, charged the 30 % penalty, recorded a no-show; the club's records show a no-show evening; nothing surfaces it beyond audit rows.
*Fix:* carry a server-anchored `occurred_unix` per event (the box has `unixNow()` after its first seed) and prefer it; drop the `>MaxEventAge` branch (keep only `claimed > now`) or resolve a clamped `BookingActivation` token ignoring expiry and judge the booking's own window; raise `AccessCodeGraveHours` beyond the documented outage horizon or never purge a code whose booking is NoShow/unstamped; re-pin the test with a slot that ended before the horizon.

**4. A replayed signed discovery OFFER rewinds a provisioned box's clock and, via the two-strike rule, strips its credential — then unsigned OFFERs are accepted and the box can be silently repointed.** *Programme-introduced (`ba292ff`, C1 clock seed).*
